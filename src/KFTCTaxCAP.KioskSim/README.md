# KFTCTaxCAP 키오스크 시뮬레이터

이 프로그램은 국세 베리어프리 키오스크(POS) 역할을 흉내 내어, KFTCTaxCAP(원캡) 프로그램에
501008(국고 상세 고지내역 조회) / 800000(카드 정보 조회) / 902614(국고 신용카드 승인요청)
3종 전문을 보내고 응답을 필드 단위로 확인하는 **테스트 겸 연동 샘플 프로그램**입니다.

실제 키오스크(POS) 업체가 원캡과 연동하는 소켓 클라이언트를 만들 때, 이 소스를 그대로 참고
샘플로 사용할 수 있도록 만들어졌습니다. 원캡 본체(WPF 앱)의 소스는 이 프로젝트에 전혀
포함되어 있지 않습니다 — 이 프로젝트는 순수하게 소켓 너머에서 원캡과 통신하는 별도 프로그램입니다.

## 실행 전제

- **KFTCTaxCAP(원캡 본체)가 먼저 실행되어 있어야 합니다.** 원캡이 `127.0.0.1:8002`에서
  소켓 서버를 열고 있어야 이 시뮬레이터가 연결할 수 있습니다. 원캡을 띄우지 않은 상태로 전송하면
  "연결 거부"가 즉시(타임아웃 없이) 표시됩니다.
- 통신 포트: **`8002`** (루프백 전용, `127.0.0.1`).

## 빌드 방법

이 폴더(`KFTCTaxCAP.KioskSim`)만 있으면 독립적으로 빌드할 수 있습니다. 다른 폴더나 파일에
의존하지 않습니다.

```
dotnet build KFTCTaxCAP.KioskSim.sln
```

Visual Studio에서는 `KFTCTaxCAP.KioskSim.sln`을 그대로 열면 됩니다. 외부 NuGet 패키지를
전혀 사용하지 않으므로(`PackageReference` 0개), 인터넷이 차단된 폐쇄망 환경에서도 별도의
`dotnet restore` 없이 바로 빌드됩니다.

- 대상 프레임워크: `.NET Framework 4.8` (`net48`)
- 플랫폼: `AnyCPU` (32bit/64bit 어느 환경에서도 실행 가능 — 원캡 본체와 달리 네이티브 32bit
  DLL을 로드하지 않기 때문입니다)

## 통신 프레임 형식

원캡과 주고받는 모든 전문은 다음과 같은 단순한 프레임 형식을 씁니다.

```
[길이 4자리 ASCII 숫자][본문]
```

- 앞 4바이트는 뒤에 이어지는 **본문의 바이트 수**를 10진수 ASCII 문자(`D4` 포맷, 예: `0706`)로
  표기한 것입니다. STX/ETX 같은 별도의 구분 문자는 사용하지 않습니다.
- 본문 길이는 전문 종류별로 고정되어 있습니다: `501008`=706바이트, `800000`=500바이트,
  `902614`=1500바이트.
- 인코딩은 **CP949**입니다. 한글 필드(기관명, 성명 등)가 포함되어 있으므로 바이트 수를 셀 때
  문자 개수가 아니라 반드시 CP949 인코딩 기준 바이트 수로 계산해야 합니다.
- 한 번의 요청·응답이 한 번의 TCP 연결입니다(연결 → 전송 → 응답 수신 → 연결 종료). 이 시뮬레이터도
  전문마다 새 연결을 엽니다.

## 중요 — 전문 필드 테이블에 대한 주의

이 소스 안의 전문 필드 정의(번호, 이름, 표현 형식, 길이, POSITION, 담당 주체)는 국세청/금융결제원
SPEC 문서를 참고해 옮겨 적은 것입니다. **SPEC 원문이 정본(source of truth)이며, 이 소스의 테이블은
어디까지나 참고용 사본입니다.** 실제 연동 개발 시에는 반드시 발주처가 제공하는 최신 SPEC 문서와
대조해 확인하시기 바랍니다. 이 소스와 SPEC이 어긋나는 부분을 발견하시면 SPEC을 우선하십시오.

## 전문 간 필드 연쇄 (앞 전문 응답 → 뒤 전문 요청)

국세 납부는 **501008 → 800000 → 902614** 순서로 진행되고, 앞 전문의 응답 필드가 뒤 전문의 요청 필드로
들어갑니다(예: 501008 응답 #17 납세 의무자 번호 → 902614 요청 #14·#36). 키오스크가 직접 구현해야 하는
부분이며, 이 시뮬레이터는 그 흐름을 그대로 보여 줍니다.

- **한 장짜리 요약표는 이 폴더의 `연쇄 필드 정리.txt`입니다.** 902614·800000 요청 필드별 출처를 정리했습니다
  (`*` = 501008 응답 필드, `@` = 800000 응답 필드).
- **규칙 전체(코드)는 `Protocol/TelegramChainMap.cs` 한 파일에 있습니다.** 어느 응답 필드가 어느 요청 필드로,
  어떤 변환을 거쳐 들어가는지 항목마다 주석으로 적었습니다. 화면(`Forms/MainForm.cs`)은 이 표를
  `ApplyChainFromResponse` 한 곳에서 적용할 뿐입니다.
- **연쇄 필드는 빈 칸으로 시작합니다.** 앞 전문의 정상 응답을 받아야 채워집니다. 채워진 칸은 색으로
  구분되고, SET 장소 열에 출처(예: `kiosk ← 501008 응답 #30+#31+#32`)가 보입니다.
- **앞 전문 응답 #7 응답 코드가 `000`일 때만 연쇄합니다.** 실패하면(#7 ≠ `000`, 응답을 받지 못함) 그
  전문에서 온 값만 비우고 다른 전문에서 온 값은 그대로 둡니다.
- **채워진 값도 전송 전에 고칠 수 있습니다.** 앞 전문을 다시 보내면 성공·실패 모두 덮어씁니다.
  순서를 강제하지는 않습니다 — 앞 응답 없이 보내면 상태 표시줄에 빈 연쇄 필드 개수만 안내합니다.
- **값 변환**: 출처가 더 긴 한글 필드(예: 징수 기관명 AHN40 → AHN20)는 CP949 기준으로 자르되 한글이
  반 글자로 잘리지 않게 합니다. 금액 합산은 두 가지입니다 — 응답 필드를 더하는 합산(902614 #27 납부 세액,
  800000 #15 납부세액)은 공백을 0으로 보고, 같은 전문 안의 합산(902614 #29 총 납부 금액 = #27 + #28)은
  더할 값 중 하나라도 비면 결과도 빈 칸입니다. 숫자 필드의 앞 `0` 채움은 전문을 만들 때 처리됩니다.
- **902614 #34 할부 개월 수**: 800000 응답 #22 카드 할부개월 LIST(2바이트 코드 연속, 예: `000203…`)에서
  고릅니다. 기본값은 첫 항목(`00` 일시불)이고, 체크카드는 `00` 하나만 옵니다. **포인트 납부는 할부 개월
  수에 60을 더한 값을 직접 입력합니다**(예: 포인트 일시불 `60`, 포인트 3개월 `63`).
- 프리셋(`kiosksim.preset.json`)은 연쇄 필드를 저장하지도 불러오지도 않습니다.
- **kiosk·원캡이 채우지 않는 숫자(N) 필드는 `0`으로 고정됩니다**(서버 요구 — 공백으로 보내면 서버가 오류 처리).
  SET 장소 열에 `서버 요구: 0 고정 (편집 불가)`로 표시되고 값 칸에 `0`이 필드 길이만큼 그대로 보이며, 그 값이
  전송됩니다(보이는 값 = 보내는 값). 대상: 501008 #5·#13·#15·#23~#28·#30~#39·#47~#52(25개), 800000
  #5·#11·#12·#13·#24·#25·#26(7개), 902614 #5·#13(2개). 필드 정의의 `zeroFilled: true`로 정해지며 별도
  변환 코드는 없습니다. 문자 계열 필드와 kiosk가 채우는 숫자 필드는 해당하지 않습니다.

> 연쇄 규칙도 SPEC 원문이 정본입니다. 다만 SPEC에 명문 근거가 있는 항목은 902614 #11·#12·#29뿐이고,
> 나머지는 업무 담당자가 확정한 값 출처를 옮긴 것입니다(`TelegramChainMap.cs` 머리 주석 참고).
> 이 표와 SPEC이 어긋나면 SPEC을 우선하십시오.

## 폴더 구조

```
Protocol/   전문 정의(필드 테이블), 고정길이 인코딩/디코딩(코덱), 전문 간 연쇄 표(TelegramChainMap.cs)
Net/        TCP 클라이언트(원캡 소켓 서버와의 통신)
Forms/      화면(WinForms)
Preset/     입력값 프리셋 로드/저장
tools/      spec_client.ps1 — PowerShell만으로 전문을 보내볼 수 있는 최소 예제 스크립트
```
