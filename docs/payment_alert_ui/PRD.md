# PRD: 결제 알림창 UI/UX 개선 (6차 범위)

> **요구사항 정본.** 순서는 `ROADMAP.md`, Task 단위 지시는 `development_plan.md`(각 Phase 착수 직전 작성)에 있다.
> Phase 번호는 앞 범위에서 이어진다(Phase 41~).
>
> 작성 2026-10-07. "사용자 확정"은 2026-10-07 대화에서 확정된 것, "**제안**"은 아직 확정되지 않았다(§6 미확정 표).
> **Phase 41 착수 전에 §6의 제안 항목을 사용자와 확정한다.**
>
> **용어**: "결제 알림창"은 `PaymentNoticeWindow`(2차 범위, Phase 13·18) — 카드 투입/긁기 요청, 거래중, PIN 입력을
> 안내하는 창이다. 확인·경고를 띄우는 모달 메시지 박스(`AlertDialog`, 5차 범위)와는 다르다.

## §0 요약

| 항목 | 결정 |
|---|---|

| 대상 화면 | 카드 요청(IC·MS) / 거래중(VanProcessing) / PIN 입력(PinEntry) 세 가지 전부(사용자 확정) |

| 가장 큰 문제 | 창 윤곽이 없어 **뒤 화면과 구분되지 않는다**(사용자 지적, §2.1) |

## §1 현재 상태 (2026-10-07 실측)

`--notice-demo`로 각 상태를 캡처해 확인했다(앱 `Views/PaymentNoticeWindow.xaml`).

| 항목 | 현재 |
|---|---|
| 창 | 600×520, `WindowStyle=None`, `Topmost`, `CenterScreen`, 배경 `#F7F7F7`. **테두리·그림자·둥근 모서리 없음** |
| 문구 | 한글 2줄(22 Bold) + 영문 2줄(16) 단일 위계. IC 요청은 4줄, MS 요청은 2줄이라 높이가 들쭉날쭉 |
| 핵심 주의 | "결제가 완료될 때 까지 카드를 빼지 마시오"가 일반 제목과 같은 무게(띄어쓰기 `때 까지` 오류 포함) |
| 거래중 | 문구 한 줄 + 신호 웨이브 + 진행광 링. 취소 버튼이 비활성인 이유 표시 없음 |

## §2 디자인 개선 항목

### 2.1 D1 — 창 윤곽 (사용자 지적 사항, 최우선)

**문제**: 창 배경 `#F7F7F7`이 흰색·밝은 회색 화면(결제창, 키오스크 POS) 위에 뜨면 경계가 사라진다.

**방법 비교**

| 방법 | 효과 | 비용·위험 |
|---|---|---|
| **A. 흰 카드 + 1px 테두리 + 둥근 모서리 + 그림자 (제안)** | 어떤 배경에서도 윤곽이 잡힘. 5차 알림창 D1과 같은 언어 | `AllowsTransparency=True` + 그림자 여백 필요. Win7 동작 |
| B. 전체 화면 스크림(뒤 화면 어둡게) | 결제 중임이 가장 확실 | 뒤 POS 화면이 가려짐, 전체 화면 창 추가, Topmost·포커스 정책 충돌 가능 → **이번 범위 밖**(§6 #2) |
| C. 상단 파란 강조선만 | 가장 단순 | 윤곽 문제 미해결 — A의 보조로만 |

**A 사양(제안)**

- 카드: 배경 **흰색**(현 `#F7F7F7` → 일러스트 원판이 배경에 묻히던 것도 해소), 테두리 1px `#DCE0E4`, 반지름 16.
- 그림자: `#1A202C`, 불투명도 0.22, 흐림 40, 아래 10(5차는 0.16/32/8 — 이 창은 더 크고 배경 구분이 더 절실해 한 단계 진하게).
- 카드 바깥 **투명 여백 40**(그림자 표시용). 창 자체는 600×520 카드 + 여백 → 680×600, `CenterScreen` 유지.
- `AllowsTransparency=True`, 배경 `Transparent`. 안쪽 `Viewbox` 750×650 구조는 그대로 카드 안에 넣는다.
- 글자 렌더링: 5차에서 확인된 문제(투명 창에서 ClearType 손실) 때문에 카드에 `RenderOptions.ClearTypeHint=Enabled`(5차 PRD §3.2 "글자 렌더링" 선례).
- 창 위치 보정: 카드(여백 제외)가 화면 중앙에 오도록 한다(5차 §3.4 "위치"와 같은 원칙).

### 2.2 D2 — 문구 위계 3단 (제안)

한글 제목 / 핵심 주의 문구 / 영문 보조를 시각적으로 분리한다.

| 층 | 용도 | 스타일(제안) |
|---|---|---|
| 제목 | "그림과 같이 카드를 넣어주세요." / "처리 중입니다."(§7, 이전 "거래중입니다.") | 22 Bold `TitleTextBrush`(현행 유지) |
| 주의 | "결제가 완료될 때까지 카드를 빼지 마십시오." | 15 SemiBold, 경고 강조색(5차 `AlertWarningFg` 계열) 또는 옅은 배경 칩 |
| 영문 | 영문 병기 | 14 Regular `SubTextBrush`(현 16 → 14, 한글보다 한 단계 아래) |

- 문구 문자열은 `PaymentNoticeBackgroundSource`/ViewModel 한 곳에서 오며, 바뀌는 것은 **분리·스타일**이다.
- `때 까지` 띄어쓰기 정정(`때까지`)은 문구 뜻 변경이 아니라 오탈자 정정이라 포함(§6 #5에서 확인).

### 2.3 D3 — 취소 버튼 (제안)

- 보조 버튼 스타일로 정리(5차 `#F2F4F6` / hover `#E6E8EC` / pressed `#DCDEE2`, 글자 `#4E5968`). 폭 140·높이 40 유지.
- **비활성(거래중) 상태**: 버튼은 옅게 표시하고 그 위/옆에 안내 한 줄 "거래 처리 중에는 취소할 수 없습니다."(영문 병기 여부 §6 #4).
- 취소 로직(`IsCancelAllowed`·`TryMarkCanceled`·ESC 훅 게이팅)은 **한 줄도 바꾸지 않는다**.

### 2.4 D4 — PIN 입력 화면 (제안)

- 4칸 입력 표시: 5차와 같은 반지름·테두리 토큰, 현재 칸 강조는 `Blue500` 2px 유지.
- 키패드: 버튼 반지름·눌림 피드백·색을 5차 버튼 토큰과 맞춘다. 3×4 배치·숫자 위치·⌫는 불변
  (보안 키패드가 아니라 고정 배치 — 변경 시 별도 보안 검토 필요, 이번 범위 밖).
- PIN 마스킹/노출 600ms 동작, 4자리 자동 진행은 불변.

### 2.5 D5 — 단계 표시 (미확정)

카드 → 거래중 → PIN을 상단에 점 3개 등으로 표시하는 안. **새 요소라 사용자 판단 필요**(§6 #1). 확정 전까지 구현하지 않는다.

## §3 유지하는 요소

- 일러스트 자산 구성과 z-order(원판 → 진행광 링 → 몸통 → 카드/화살표/오버레이), `PaymentNoticeBackgroundSource` 매핑.
- 상태 전환 방식(창 재생성 없이 State 변경 + 크로스페이드), 신호 웨이브·진행광 링·화살표 바운스 애니메이션.
- Topmost·ShowInTaskbar=False·Owner 미지정(홈 화면 활성화 방지, P13-3).
- 전역 ESC 키보드 훅(`PaymentNoticeKeyboardHook`) 동작.
- 컴팩트(작은 화면) 대응: 기존 `_VERYSMALL` 자산 전환 규칙 불변. 카드 여백·그림자도 컴팩트에서 어긋나지 않는지 검증 항목에 포함.

## §4 구현 원칙

- `net48`/x86, 외부 패키지 추가 없음. Win7 SP1/.NET 4.8에서 동작(`AllowsTransparency`·`DropShadowEffect` OK, DWM 전용 API 금지).
- 새 토큰은 `Themes/Colors.xaml`·`Themes/Alert.xaml` 재사용 우선, 필요한 것만 추가(결제 알림창 전용 값은 `PaymentNoticeWindow.xaml` 리소스 또는 신규 `Themes/PaymentNotice.xaml`).
- 코드비하인드(`PaymentNoticeWindow.xaml.cs`, 641줄)의 애니메이션·레이어 제어는 **그대로 둔다**. 이번 범위는 XAML 스타일 중심 변경이다. MVVM 전환 같은 구조 개편은 하지 않는다.
- 의존 방향 `Views → ViewModels → Services → Protocol` 유지.

## §5 검증 방법

- **화면 캡처 전/후**: `__COMPAT_LAYER=RunAsInvoker`로 `--notice-demo`, `--notice-van-processing-test`, `--notice-pin-test` 실행(manifest는 건드리지 않는다). 밝은 바탕·어두운 바탕·결제창 위 세 경우에서 윤곽 확인.
- **일반/컴팩트 모드** 각각 캡처.
- **회귀**: `--payment-flow-test`, `--presenter-test`, `--notice-van-processing-test`(VanProcessing 중 ESC 무시, 5초 후 IC 전환 시 취소 가능) — 취소 1회 보장·게이팅 유지.
- **실제 화면 E2E**: 실제 결제 흐름(KioskSim → 원캡)에서 카드 요청 → 거래중 → 응답까지 한 번 통과(리더기 실기 사용 시 사용자에게 먼저 확인).
- 사용자 육안 확인 후 완료. Win7 실기가 없으면 "Win7 미확인"으로 기록(추측으로 완료 표시 금지).
