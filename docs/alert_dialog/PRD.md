## §3 새 알림창 설계

### 3.1 API (ViewModel·View 공용 계약)

```
enum AlertKind    { Info, Warning, Error, Success, Question }
enum AlertButtons { OK, OKCancel, YesNo }        // 원본의 YesNoCancel은 미구현이었으므로 두지 않는다
enum AlertResult  { OK, Cancel, Yes, No }

record AlertMessage(AlertKind Kind, string Text)  // ViewModel → View 이벤트 페이로드(WPF 타입 없음)

// View 쪽 헬퍼 — MessageBox.Show 자리를 그대로 대체
AlertResult AlertDialog.Show(Window? owner, string text, string caption,
                             AlertKind kind, AlertButtons buttons = AlertButtons.OK)
```

- `AlertKind`/`AlertButtons`/`AlertResult`/`AlertMessage`는 **WPF 타입을 참조하지 않는다** — ViewModel이 쓴다.
- `text`의 첫 줄바꿈(`\r\n` 또는 `\n`) 앞이 제목, 뒤가 본문(사용자 확정). 줄바꿈이 없으면 제목만.
- `caption`은 창 `Title`(작업 표시줄·Alt+Tab·접근성 이름)로만 쓰고 화면에는 그리지 않는다(원본 동일). 기존
  호출부의 캡션(`가맹점 설정`, `리더기 설정`, `전표 출력`)을 그대로 넘긴다.
- 알림창 자체도 MVVM으로 만든다(CLAUDE.md) — `AlertDialogViewModel`(제목·본문·종류·버튼 목록·결과),
  창 이동(DragMove)·포커스·알림음처럼 창 핸들에 묶인 것만 코드비하인드.

  `…출력할` / `수 있습니다.`처럼 문장 중간에서 넘어가면 어색하다). 문장이 길면 `\n`으로 의미 단위에서 직접 나누거나 축약한다.

  응답 값 등)이 들어오는 경우의 안전장치다.
